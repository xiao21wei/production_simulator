## 0. 本文目标

把原 `production_simulator` 里"按 `machine_id + 时间点 t` 取历史窗口喂给故障预测模型"的能力，从**仿真进程内的函数调用**，改造成**独立的流式数据模拟服务（HTTP API）**：

- 服务只负责**产数据 / 取窗口 / 取标签**，**不再加载模型、不做推理**；
- 故障预测模型部署在外部的「异常管控平台」，由该平台调用本服务的 `/window` 取数、自行推理；
- 另提供一组接口给「调度展示平台」的**前端页面**做实时数据流展示与故障标记；
- 数据集**预生成若干台机器**，机器数超出时**按需确定性扩展**；
- 保留完整说明、接口文档与数据字典，便于后续查阅与三方对接。

## 3. 核心语义：时间、窗口、取模（本方案最关键部分）

### 3.1 原 `get_history_window` 的精确定义

```python
end_row_idx   = 100 + t * 2
start_row_idx = end_row_idx - 100        # = t * 2
window = df.iloc[start_row_idx:end_row_idx][15个特征列].to_numpy()   # (100, 15)
```

即：时间点 `t` 的模型输入 = `rows[ 2t : 100 + 2t )`，**不含** `row 100+2t` 本身；该行恰是时间点 `t` 自身的 2 行中的第 1 行。

### 3.2 时间点 ↔ 行 的映射

| 概念 | 公式 |
|---|---|
| 数据集行数 | `L` |
| 采样步长 | `step = 2`（**1 时间点 = 2 行**） |
| 预热/历史缓冲 | `warmup_rows = 100`（= 50 个时间点的历史，位于 `rows[0:100]`） |
| 时间点 `t` 的窗口 | `rows[ 2t : 100+2t )`，共 100 行 |
| 时间点 `t` 自身的行 | `rows[ 100+2t : 100+2t+2 )` |
| 时间点 `t` 的标签 | 读上述 2 行，任一 `label=1` 即 `label(t)=1` |

### 3.3 有效时间点数 `T` 与约束

窗口不越界要求 `100 + 2t ≤ L`：

```
T = (L - 100) // 2 + 1          # 合法 t ∈ [0, T-1]
```

例：`L=21197` → `T = 21097//2 + 1 = 10549`，`t_effective ∈ [0, 10548]`，验证 `t=10548` 时 `row_end=21196 ≤ L` ✓。

标签查询 `100 + 2(t-t1) + 2 ≤ L` 在 `t` 接近 `T-1` 时可能超出 2 行——**修复**：`end = min(100+2t_eff+2, L)`，不足 2 行时按实际行数读取，越界返回 0（见 §3.6）。

### 3.4 取模循环与 wrap 处理

```
t_effective = ((t % T) + T) % T          # t 由外部单调递增，服务内部取模
row_start   = 2 * t_effective
row_end     = row_start + 100
```

- 用户明确：`t` 无上限但不大 → 取模循环是预期行为，服务必须保证任意 `t` 都返回**合法、不越界、不含未来数据**的窗口。
- 每个窗口都是 `rows[2t : 100+2t]`（严格历史/当前），**标签不进入窗口**，因此取模不会引入未来数据、也不存在数据泄漏。
- **wrap 不连续**：`t` 从 `T-1` 回到 `0` 时，窗口从"数据集尾部"跳到"数据集头部"。若下游把连续窗口当一条流拼接，会出现跳变。三层处理（均为选项 3 范围内的低风险修复）：
  1. **guard 段**（默认开启、不改变数据分布）：生成时保证**头部 100 行预热段**与**尾部最后一个窗口**都落在**正常段**，且尽量取自同一正常基底块的连续区间；使 seam 两侧都是"正常数据"。
  2. **seam 标记**（默认开启）：`/window` 与 `/stream` 返回 `wrapped` / `wrapped_at`，前端在 seam 处不画连线或打一条竖直虚线；模型端每个窗口独立推理，不受影响。
  3. **`T` 足够大**：`min_len=10000` 时间点使 `T≈10^4`，实际演示几乎不会触发 wrap；即便触发也有 1、2 兜底。
- 可选增强 `smooth_wrap`（默认关闭）：把尾部与头部拼接处做一次线性淡入淡出对齐，代价是改变少量真实样点，需单独验证——**保守起见默认关闭**。

### 3.5 标签、预警区与 `prediction_horizon` 的对齐

模型配置 `prediction_horizon = H = 20`（**20 个时间点 = 40 行**）。据此定义两类真值（均为附加元数据，**不进模型输入**）：

| 字段 | 定义 | 用途 |
|---|---|---|
| `label(t)` | 时间点 `t` 是否处于异常（读 `rows[100+2t : 100+2t+2]`） | 故障中标记（朱红实心带） |
| `warn(t)` | 若 `∃ s ∈ [t, t+H)` 使 `label(s)=1` 则为 1 | **预警提前区**（橙色斜纹带） |

- 二者重叠时（异常已发生）以 `label` 优先显示故障色。
- `get_label(df,t,t1)` 的旧语义保留为 `/labels?t=&t1=`：`t1` 为"回溯多少时间点"。**修复**：`t - t1 < 0` 时直接返回 0（流开始前无真值），不再用旧代码里不可达的 `if start_row_idx < 0` 分支。跨 seam 的 `t-t1` 查询按 `t_effective - t1` 取行并附 `wrapped_target` 标记，文档注明其不具因果意义。
- 前瞻区接近数据集尾部时（`t_effective + H > T`），`warn` **截断到 `T-1`，不循环到数据集头部**；`/stream` 每帧返回 `horizon_wrap=true` 明确标注，`/window` 返回 `cycles=t//T`。避免把"数据集开头"错当成"未来真值"（评审指出：循环真值会使评估口径失效）。
- 前端在时间点 `t` 着色取**当前帧** `label(t)` / `warn(t)`，不用 `t+H` 的单点标签，否则故障带会整体右移。

> **⚠ 口径诚实边界（评审 P0-2，必须写进对接文档）**
> 旧 `get_label(df,t,t1)` 的 `t1` 是**向后回看**（旧仿真器 `handleFailureDetectEvent` 用 `t1=10` 检测"10 个时间点前是否发生故障"，属事后检测）；而 `prediction_horizon` 是模型配置里的**前瞻**参数。二者方向相反，且**已部署 CNN-LSTM 训练时使用的具体标签口径在本仓库不可见**。
> 因此 `warn(t)` 在本服务里只是**供前端展示与离线评估的辅助标签**，不宣称等于该模型的训练目标。与「异常管控平台」联调时必须确认其训练标签口径：
> - 若为 `[t, t+H)` → 与当前 `warn` 一致；
> - 若为 `[t+1, t+H)` 或单点 `label(t+H)` → 调整 `config.yaml → contract.prediction_horizon` 与 `registry._warn_labels` 的区间并升 `contract.version`、重跑 §5.4 回归；
> - 若训练目标其实是回看/检测型 → `warn` 仅用于展示，不得用于命中/误报评估。
> 另：突发型异常在发生前 20 个时间点窗口内并无物理前兆，`warn=1` 但未必可预测；评估应按事件级区分"可提前预警"与"事后检测"，不要按行级统计。

### 3.6 旧代码缺陷清单 → 修复对照（决策 2 的"只修缺陷"落地）

| # | 缺陷 | 影响 | 修复 | 默认 |
|---|---|---|---|---|
| D1 | `end_row_idx > len(df)` 直接抛错，且 `t` 无上界 | 流式跑一会必崩 | 取模 `t%T` + 边界裁剪，任意 `t` 恒合法 | **开** |
| D2 | `start_row_idx < 0` 后 `if start_row_idx<0: return 0` 不可达 | 早期标签判断潜在错误 | `t-t1<0` 直接返回 0；标签读取按实际行数裁剪 | **开** |
| D3 | 无固定预生成，`machine_id` 超量即 `load_data→None` 崩溃 | 机器数扩展不可用 | 随包附带 15 台原样读取 + 按需确定性惰性生成(原子落盘) + 并发锁 | **开** |
| D4 | 头部/尾部无正常段保证，wrap 处可能"异常片段紧接数据头" | seam 处假异常/跳变 | head/tail guard 正常段 + `wrapped` 标记 | **开** |
| D5 | 常量特征无说明，易被前端误画 | 展示噪声 | 数据字典标注 `LPS/Oil_level/Caudal_impulses` 为常量，展示层剔除（**模型输入仍保留 15 列**） | **开** |
| D6 | 无 `warn` 预警提前区标签 | 前端无法直观展示"可提前预警" | 生成附加 `warn` 列（不进模型输入） | **开** |
| D7 | 无元信息/契约自描述 | 异常平台对接靠口头约定 | `/meta` 返回特征顺序、量纲、`T`、形状、归一化等 | **开** |
| E1 | 异常永远是同一段、逐字重复 | 模型易记忆、观感单一 | 从同一基底派生多个异常模板（不同截断/相位/微扰） | 关 |
| E2 | 正常段来自固定两块、机器间无差异 | 各机数据雷同 | 逐机器确定性微小增益/偏移 + 轻噪声（仅连续特征） | 关 |
| E3 | 每轮恰好 1 异常，排布半规律 | 可预测 | 泊松/指数间隔随机化异常位置 | 关 |
| E4 | 无渐变劣化前兆 | 故障过于突兀 | 异常前短 ramp（正常↔异常基底线性过渡），与 H 对齐 | 关 |
| E5 | wrap 处硬跳变 | 展示不连续 | 尾部→头部线性淡入淡出对齐 | 关 |

> E1–E5 属"更合适的异常分布"候选，**默认全部关闭**，逐个打开、逐个用 §9 的验收项验证后再决定是否纳入；这正是"效果可保障"的落地方式。

## 4. 数据集与异常分布方案

### 4.1 原方案复盘

以一段真实 MetroPT 故障片段为唯一基底（4040 行，39 行异常），按「正常段随机长度切片 + 同一段异常首尾截断」反复拼接成每台约 2.1 万行的序列，`seed` 固定。异常占比约 2%，集中在短突发。

### 4.2 缺陷清单

见 §3.6 的 D1–D7 与 E1–E5。归纳：**可运行性缺陷（越界/扩展/wrap/无契约）** 与 **分布缺陷（重复、无逐机差异、半规律、无前兆）** 两类。

### 4.3 三套候选对比与选择结论

| 维度 | ① 参数化全合成 | ② 混合真实基底 | ③ 沿用原方案+修缺陷（**已选**） |
|---|---|---|---|
| 可控性 | 高 | 中 | 中（参数固定、易复现） |
| 真实性 | 取决于建模 | 较高 | **保留真实片段观感** |
| 可复现性 | 高 | 中 | **高（seed 固定）** |
| 与已部署 CNN-LSTM 兼容 | 需重新验证 | 需重新验证 | **逐值一致，可回归验证** |
| 效果可保障 | **难**（新分布模型未必吃得准） | **难** | **高（默认不变 + 逐项可验）** |
| 实现成本 | 高 | 中 | **低** |

**结论**：按你的选择采用 **③**。理由"1、2 的效果很难保障"——旧模型是在这套真实基底分布上训练的，换分布会让预测效果不可预期；③ 在**完全不动模型输入分布**的前提下，把可运行性缺陷一次性修净，并把分布改进做成默认关闭、可逐项验证的开关。

### 4.4 选项 3 下的"更合适的方案"

分两层：

- **保底层（D1–D7，默认开启）**：只修工程缺陷，**不改变任何特征值、不改变异常片段内容、不改变拼接参数**，因此模型输入与旧版逐值一致。这是"稳"的核心。
- **增强层（E1–E5，默认关闭）**：在不换基底、不换模型的前提下，让异常分布在观感与统计上更合理。每项一个开关，开启后只影响"新增机器/重新生成"的数据；已有 `machine_*.csv` 不受影响，便于对照 A/B。

    - **E1 多异常模板**：把 39 行真实异常按不同截断窗口 / 起止相位 / 轻微时间重采样，派生出 K 个模板（默认 K=4）；每台机器、每次异常随机（seed 决定）选一个，避免逐字重复。
    - **E2 逐机器扰动**：对 7 个连续特征施加 `x' = x * (1+g_i) + b_i + ε`，`g_i,b_i ~ N(0, 0.01)`、`ε ~ N(0, jitter_std)`，`seed = base_seed + machine_id` 决定；二值/常量特征不动，保证 15 列结构与量纲基本不变。
    - **E3 泊松排布**：异常间隔由 `random.randint(250,1250)` 改为按指数分布采样（均值可配），打散半规律性。
    - **E4 渐变前兆**：异常起点前插入一段 `ramp_len`（默认 = H=20 个时间点）的 `normal→anomaly` 线性过渡，对应 `warn` 区，使"可提前预警"在波形上可见。
    - **E5 平滑 wrap**：见 §3.4。

> 所有增强只作用于**生成期**，不进入「模型输入窗口」的契约字段（窗口仍是 100×15 原始浮点、固定顺序）。开关与参数集中在 `config.yaml`，文档记录每个开关的预期效果与验证方法。

### 4.5 预生成 + 按需扩展 + 确定性

- 启动时确保 `machine_0..machine_{N-1}.csv`（`N = pre_generated_machines`，默认 **15**）存在；**已附带的 15 台原样读取、绝不重新生成**（这是 `/window` 与旧版逐值一致的前提）；仅缺失的按 `seed = base_seed + machine_id` 生成并落盘。
- `machine_id ≥ N` 时，首次请求触发**惰性生成**：`registry` 加 `threading.Lock`，生成后写 CSV 并加入内存缓存（LRU，避免常驻全量）；**同一 `machine_id` 无论何时、重启与否都得到完全相同的数据**。
- `/machines` 返回每台 `rows / T / 是否预生成 / 异常占比`，便于调度平台展示机器列表。
- 生成逻辑与旧版 `generate_machine_datasets` 参数对齐（`min_len / normal_len_* / anomaly_len_*`），保证"默认行为贴近原版"。

## 5. 模型输入契约（完全一致）

### 5.1 契约表

| 项 | 值 |
|---|---|
| 窗口 | `100` 行 × `15` 列 |
| 时间步长 | `step=2` 行 / 时间点 |
| 预热 | `100` 行 |
| 特征顺序 | 见 §4.6 `contract.features`（**固定，禁止增删/重排**） |
| 值 | **原始浮点，不做归一化** |
| 送入模型形状 | `(1, 15, 100)` = (Batch, Channel, Length) |
| dtype | `float32` |
| 标签 | **不随 `/window` 返回**（防泄漏）；由 `/labels`、`/stream` 单独提供 |

### 5.2 从 `/window` 响应到模型张量

`/window` 默认返回 `layout=time_major` 的 `data[100][15]`（与旧 `df.to_numpy()` 完全一致）。异常管控平台两种用法：

```python
win = resp["window"]["data"]                     # 100 x 15, time-major
x = torch.tensor(win, dtype=torch.float32)       # (100, 15)
x = x.unsqueeze(0).permute(0, 2, 1)             # (1, 15, 100)  ← 与旧版一致
```

为省去平台端转置，接口另提供 `layout=channel_major`（返回 `data[15][100]`），平台可直接 `torch.tensor(data).unsqueeze(0)`。**默认 `time_major` 以保证与旧版逐值一致**。

### 5.3 数据泄漏隔离

- `/window`：只有 15 个特征值 + 元信息，**无 `label` / `warn`**。
- `/labels`、`/stream`：返回真值，仅供展示与评估。
- 三者物理上分开，杜绝"预测输入里混入答案"。

### 5.4 契约一致性回归测试（关键验收，直接回应"效果可保障"）

`tests/test_contract_regression.py`：

1. 旧版 `get_history_window(df,t)` / `get_label(df,t,t1)` 的语义以**冻结副本**内置于 `tests/`（标准库 `csv` 实现，不依赖原工程），以随包附带的 `machine_0.csv` 为固定夹具；
2. 取新服务 `/window?machine_id=0&t=` 的 `window.data`；
3. 断言二者**逐值相等**（形状 `(100,15)`、特征顺序一致）；另验证 `t>=T` 取模等价于旧版 `t%T` 处窗口、`channel_major` 为转置、`/window` 响应不含 `label/warn`、旧版 `get_label` 亦逐值一致；
4. 「同模型概率一致」由第 3 步蕴含（同一模型、eval 模式、输入张量逐值相同则输出必然相同）；如需实跑，在异常管控平台侧用同一权重加一条回归。

**当前状态：18 个测试全部通过，契约回归已实跑验证。** 这直接把决策 2「效果可保障」落成了可复现的验收项，且夹具是**原样复制的旧 CSV**、不依赖任何新生成数据。

## 7. 前端展示设计（摘要，详见《数据与前端对接说明》）

### 7.1 多量纲 / 混合类型展示策略

不把 15 个特征画在同一张原始值图里（量纲从 0.03 到 76、还混 0/1 与常量）。采用：

- **小多图（small multiples）**：3–4 张纵向堆叠的折线子图，**共享 x 轴（时间点 t）**，每张**独立 y 轴**并标注真实量纲；这是处理"不同量纲"的核心手段。
- 可切换「归一化叠加以 [0,1]」视图用于看相关性，但默认展示原始值。
- **二值特征**用底部一条紧凑「状态轨」（0/1 色块条）表达开关翻转，不画成折线。
- **当前值卡片（KPI strip）**：显示所选特征的最新值、min/max、单位。
- **特征选择器**：默认勾选推荐子集，可自行增删。

### 7.2 推荐展示子集

- 连续：`TP2`、`Oil_temperature`、`Motor_current`（代表性、量纲各异、对故障敏感），可选 `DV_pressure`。
- 二值：`COMP`、`DV_eletric`、`Towers`、`MPG`、`Pressure_switch`（状态轨）。
- **剔除**：`LPS`、`Oil_level`、`Caudal_impulses`（常量，仅保留在模型输入）。

### 7.3 故障 / 预警标记配色

采用 **Okabe-Ito 色盲友好调色板**（正常=蓝、预警=橙、故障=朱红，避开红绿对立），颜色 + 形态 + 纹理 + 文字四重冗余：

| 状态 | 判定 | 颜色 | 形态/纹理 |
|---|---|---|---|
| 正常 | `label=0, warn=0` | 蓝 `#0072B2` | 白底实线、无填充 |
| 预警提前区 | `warn=1` | 橙 `#E69F00` | 45° 斜纹带 + "提前窗 H=20" 图例文字 |
| 故障中 | `label=1` | 朱红 `#D55E00` | 实心带 + 朱红散点 + 加粗 |
| 模型预测预警（可选回传） | 平台 `p≥0.93` | 紫红 `#CC79A7` | 概率折线 + 阈值虚线 |
| 预热/不可用 | 数据未就绪 | 灰 `#999999` | 斜纹 + "预热中"文字 |
| 回绕 seam | `t_effective` 归零 | 深灰 | 竖直虚线 + "回绕"文字 |

图例写明判定条件（非仅色块），固定图例常驻；悬浮 tooltip 显示该时间点各特征原始值与标签。详见《数据与前端对接说明》C.4。

### 7.4 时钟与轮询

- 前端维护 `t`（单调递增计数器，服务内部取模，前端无需关心 `T`）。
- 按节拍 `setTimeout` 调用 `GET /stream?machine_id=&from_t=t&count=1`，追加到长度 120 的环形缓冲并淘汰最旧帧；`speed` 1×/2×/4× → 500/250/125ms。
- 播放 / 暂停 / 变速 / 回放 / 跳到某台机器：因时钟在前端，全部本地实现，不依赖服务端。
- `wrapped_at` 用于 seam 处断开连线并标"回绕"；`horizon_wrap` 帧的前瞻区已截断到 `T-1`，不计入累积统计。

### 7.5 可集成性

- 纯静态 `index.html` + **原生 Canvas 2D**，**零 CDN / 零外部依赖 / 无构建**，离线与内网可用；服务开启 CORS（默认 `["*"]`）。
- 既可用 iframe 嵌入，也可把「图表组件 + 数据适配层」移植进新平台；**数据适配层只依赖 `/meta` + `/stream` 两个契约**，与页面其它部分解耦。
- 文档说明如何在新平台里替换为 WebSocket/SSE（本期不做，仅留接口形态）。

## 8. 工程化要点

- **配置**：`config.yaml` + `app/config.py` 默认值；`contract` 段一旦改动即视为契约变更，需重跑回归并升 `contract.version`；15 特征顺序由 `app/data/features.py` 单一维护。
- **惰性加载与并发**：`registry` 用 `Lock` 包裹"检查→生成→临时文件→原子 rename→缓存"，避免并发写坏；缓存用 `functools.lru_cache(maxsize=8)`。
- **缓存**：`machine_id → CSV 行 + 预计算的 point_label/warn`，取时惰性加载；窗口切片为纯切片。
- **CORS**：`allow_origins` 可配，默认 `["*"]`（不写死任何外部域名，便于换服务器）。
- **错误码**：统一 JSON 错误体 `{code, message, detail}`；`400` 参数错/校验失败、`404` 文件不存在、`422` 数据集过短；`RequestValidationError` 也包成同一格式。
- **无状态**：服务本身无会话状态，`t` 完全由调用方驱动，便于水平扩展。

### 8.1 自包含与可移植（本次追加的硬约束）

目标：**把 `simulator/` 这一个文件夹整体打包到别的服务器即可运行**。

| 约束 | 落地方式 |
|---|---|
| 不依赖原工程 | **不改动、不引用** `production_simulator/`；所需数据已复制进 `data/` |
| 无绝对路径 | 代码/配置/文档一律用**相对工程根**的路径（如 `data/anomaly.csv`），禁止硬编码 `/home/...` |

## 9. 测试与验收（逐条不变量）

**窗口 / 取模**
1. 任意 `machine_id≥0, t≥0`：`window.data.shape == (100,15)`、`row_end ≤ L`、无 `NaN/Inf`。
2. `t_effective == t % T`、`row_start == 2*t_effective`、`row_end == row_start+100`。
3. `wrapped == (t ≥ T)` 且 `t_effective` 回绕正确。
4. 同一 `(machine_id,t)` 多次请求、服务重启后**完全一致**（可复现）。

**契约**
5. §5.4 回归测试：与旧 `get_history_window` 逐值一致、同模型概率一致（**最关键**）。
6. `/meta` 的 `features` 顺序与 `/window` 列顺序、CSV 表头一致。
7. `/window` 响应中**不含** `label/warn` 字段。

**生成**
8. `machine_id ≥ N` 按需生成后落盘，重启结果不变；并发 10 路请求只生成一次。
9. 各机 `rows / T / 异常占比` 在预期区间；默认配置下异常占比 ≈ 2%。
10. 头部 100 行与 `t=T-1` 窗口均为 `label=0`（wrap 平滑前提）。

**标签 / 展示**
11. `label(t)` 与 `get_label(df,t,0)` 一致；`warn(t)` 与 `[t,t+H)` 内是否异常一致。
12. `/stream` 帧数与 `count` 一致，`wrapped_at` 正确标注 seam。
13. 前端红/橙标记与 `label/warn` 一一对齐；常量特征不出现在图表里。

**增强开关（逐个开启后）**
14. 每个 `E*` 开启后重新跑 5/9/10；与关闭态对照，确认模型输入契约仍成立、效果符合预期，再决定是否纳入默认。
