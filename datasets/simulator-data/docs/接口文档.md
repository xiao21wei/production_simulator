## 1. 通用约定

| 项 | 约定 |
|---|---|
| 协议 | HTTP/1.1，JSON（`application/json; charset=utf-8`） |
| Base Path | `/api/v1` |
| 入参类型 | 全部为 query 参数；`machine_id`、`t`、`from_t`、`count`、`t1` 均为整数 |
| 时间点 `t` | **非负整数、无上限**；服务内部按 `t % T` 取模循环，调用方无需关心 `T` |
| 特征顺序 | 固定 15 列，见 `GET /meta`，**不可增删改排** |
| 数值 | 原始浮点，**不归一化**；`null`/`NaN` 不会出现 |
| CORS | 默认对展示页来源放行，可配 `server.cors_origins` |
| 部署 | 地址/端口由 `server.*` 或 `HOST`/`PORT` 环境变量决定；工程内无绝对路径，整体打包改端口即可在别的服务器运行 |
| 错误体 | 统一 `{ "code": <int>, "message": <str>, "detail": <any> }`；FastAPI 自带的参数校验错误(`RequestValidationError`)也被包成同一格式并返回 400 |

### 全局错误码

| HTTP | code | 含义 |
|---|---|---|
| 400 | 400 | 参数非法（负数、缺参、`count` 超上限等） |
| 404 | 404 | `machine_id` 不存在且 `allow_lazy_generate=false` |
| 422 | 422 | 数据集过短，无法凑出合法窗口（理论上默认配置不会触发） |
| 503 | 503 | 该机器数据集正在生成中，稍后重试 |
| 500 | 500 | 内部错误 |

### 固定特征顺序（`contract.features`）

```
[0] TP2  [1] TP3  [2] H1  [3] DV_pressure  [4] Reservoirs
[5] Oil_temperature  [6] Motor_current  [7] COMP  [8] DV_eletric
[9] Towers  [10] MPG  [11] LPS  [12] Pressure_switch
[13] Oil_level  [14] Caudal_impulses
```

## 2. `GET /api/v1/window` —— 模型输入窗口（核心）

供**异常管控平台**取数，返回喂给 CNN-LSTM 的窗口。**不含任何标签**。

### 请求参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `machine_id` | int ≥ 0 | 是 | — | 机器 ID；≥ 预生成数时按需确定性生成 |
| `t` | int ≥ 0 | 是 | — | 时间点；内部取模 `t % T` |
| `layout` | enum | 否 | `time_major` | `time_major`(100×15，与旧版一致) / `channel_major`(15×100) |

### 响应 Schema

```
WindowResponse
├── machine_id      int
├── t               int            # 原始传入值
├── t_effective     int            # t % T
├── wrapped         bool           # t >= T
├── cycles          int            # t // T，已回绕的周期数
├── T               int            # 该机器有效时间点数
├── contract        object         # 见 /meta 的契约子集
└── window          object
    ├── rows        int = 100
    ├── cols        int = 15
    ├── layout      string
    ├── features    string[15]     # 列顺序(= contract.features)
    ├── row_start   int            # = 2 * t_effective
    ├── row_end     int            # = row_start + 100 (不含)
    ├── dtype       "float32"
    ├── normalization "none"
    └── data        float[][]      # time_major: data[100][15]; channel_major: data[15][100]
```

### 示例

```bash
curl "http://localhost:8000/api/v1/window?machine_id=0&t=12345"
```

```json
{
  "machine_id": 0,
  "t": 12345,
  "t_effective": 1796,
  "wrapped": true,
  "cycles": 1,
  "T": 10549,
  "contract": {
    "window_size": 100, "step": 2, "warmup_rows": 100,
    "prediction_horizon": 20, "model_input_shape": [1, 15, 100],
    "normalization": "none", "version": "1.0"
  },
  "window": {
    "rows": 100, "cols": 15, "layout": "time_major",
    "features": ["TP2","TP3","H1","DV_pressure","Reservoirs","Oil_temperature",
                 "Motor_current","COMP","DV_eletric","Towers","MPG","LPS",
                 "Pressure_switch","Oil_level","Caudal_impulses"],
    "row_start": 3592, "row_end": 3692,
    "dtype": "float32", "normalization": "none",
    "data": [[-0.012, 8.334, 8.324, -0.022, 8.336, 58.8, 0.0425, 1.0, 0.0, 1.0, 1.0, 0.0, 1.0, 1.0, 1.0],
             "... 共 100 行 ..."]
  }
}
```

### 平台端使用（与旧 `online_inference.predict` 完全等价）

```python
import torch
r = requests.get(URL, params={"machine_id": mid, "t": t}).json()
win = r["window"]["data"]                      # 100 x 15, time_major
x = torch.tensor(win, dtype=torch.float32)     # (100, 15)
x = x.unsqueeze(0).permute(0, 2, 1)           # (1, 15, 100)
prob = model(x)                                # 与旧版逐值一致
```

或用 `layout=channel_major` 省去转置：

```python
r = requests.get(URL, params={"machine_id": mid, "t": t, "layout": "channel_major"}).json()
x = torch.tensor(r["window"]["data"]).unsqueeze(0)   # (1, 15, 100)
```

> **契约一致性**：`time_major` 的 `data` 与旧 `get_history_window(df, t).tolist()` 逐值相等（由回归测试保证）。

## 3. `GET /api/v1/stream` —— 前端展示帧/批次

供**前端展示页**按节拍拉取一帧或一批数据，含**真值标签与预警标记**（仅用于展示，不喂模型）。

### 请求参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `machine_id` | int ≥ 0 | 是 | — | 同 `/window` |
| `from_t` | int ≥ 0 | 否 | `0` | 起始时间点（单帧调试时可直接用 `t`） |
| `t` | int ≥ 0 | 否 | — | 单帧快捷参数，等价于 `from_t=t&count=1` |
| `count` | int 1..300 | 否 | `1` | 返回帧数（一批） |
| `features` | string | 否 | 推荐子集 | 逗号分隔的特征名；不传则返回数据字典中 `display=true` 的子集 |

### 响应 Schema

```
StreamResponse
├── machine_id        int
├── T                 int
├── prediction_horizon int = 20
├── features          string[]          # 本批返回的列(顺序固定)
├── frames            Frame[]
│   ├── t             int               # 原始时间点
│   ├── t_effective   int               # t % T
│   ├── wrapped       bool
│   ├── cycles        int               # t // T
│   ├── horizon_wrap  bool              # t_effective + H > T（前瞻区跨数据集尾部）
│   ├── values        { name: float }   # 各特征原始值
│   ├── label         int (0/1)         # 该时间点是否异常(朱红实心带)
│   └── warn          int (0/1)         # [t, t+H) 内是否将异常(橙色斜纹带)
└── wrapped_at        int[]             # 本批内发生回绕的帧下标, 用于断开连线
```

### 示例

```bash
curl "http://localhost:8000/api/v1/stream?machine_id=0&from_t=200&count=3"
```

```json
{
  "machine_id": 0,
  "T": 10549,
  "prediction_horizon": 20,
  "features": ["TP2","Oil_temperature","Motor_current","COMP","DV_eletric","Towers","MPG","Pressure_switch"],
  "frames": [
    {"t":200,"t_effective":200,"wrapped":false,"cycles":0,"horizon_wrap":false,
     "values":{"TP2":-0.013,"Oil_temperature":58.7,"Motor_current":0.0425,
               "COMP":1.0,"DV_eletric":0.0,"Towers":1.0,"MPG":1.0,"Pressure_switch":1.0},
     "label":0,"warn":0},
    {"t":201,"t_effective":201,"wrapped":false,"cycles":0,"horizon_wrap":false,
     "values":{"TP2":-0.012,"Oil_temperature":58.9,"Motor_current":0.0430,"COMP":1.0,"DV_eletric":0.0},
     "label":0,"warn":1},
    {"t":202,"t_effective":202,"wrapped":false,"cycles":0,"horizon_wrap":false,
     "values":{"TP2":9.87,"Oil_temperature":71.2,"Motor_current":5.9,"COMP":0.0,"DV_eletric":1.0},
     "label":1,"warn":1}
  ],
  "wrapped_at": []
}
```

> `warn=1` 而 `label=0` 即"预警提前区"；`label=1` 为"故障中"（红色优先于橙色）。

## 4. `GET /api/v1/labels` —— 标签/真值查询

对应旧 `get_label(df, t, t1)`，供异常平台评估与前端校验。

### 请求参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `machine_id` | int ≥ 0 | 是 | — | |
| `t` | int ≥ 0 | 是 | — | 时间点 |
| `t1` | int ≥ 0 | 否 | `0` | 回溯多少时间点；返回时间点 `t - t1` 的标签 |

### 响应

```json
{ "machine_id": 0, "t": 210, "t1": 10, "t_effective": 210,
  "target_effective": 200, "label": 1, "wrapped_target": false,
  "note": "label=1 表示时间点 200 处于异常" }
```

- `t - t1 < 0`（流开始前）→ 返回 `label: 0`。
- 跨 seam 的回溯按 `t_effective - t1` 取行并置 `wrapped_target: true`，文档注明此类查询不具因果意义。
- **口径提示**：旧 `t1` 是**回看**（旧仿真器用 `t1=10` 检测"10 个时间点前是否故障"），与 `prediction_horizon` 的**前瞻**方向相反。前瞻口径请用 `/warn`，且联调时须与异常管控平台确认其模型训练标签口径（见《实施方案》§3.5 诚实边界）。

### 4.1 `GET /api/v1/warn` —— 预警提前区查询

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `machine_id` | int ≥ 0 | 是 | — | |
| `t` | int ≥ 0 | 是 | — | 时间点 |

```json
{ "machine_id": 0, "t": 210, "t_effective": 210,
  "prediction_horizon": 20, "warn": 1, "label": 0 }
```

`warn(t)=1` 表示 `[t, t+20)` 内将发生故障（前端橙色斜纹预警带）。接近数据集尾部时该区间**截断到 `T-1`，不循环到头部**；`/stream` 对应帧会带 `horizon_wrap=true`。

## 8. 两方对接步骤

### 8.1 异常管控平台（模型侧）

1. `GET /meta` → 读取 `contract`（特征顺序、`model_input_shape`、归一化方式）。
2. 每个时间点：`GET /window?machine_id=&t=&layout=...` → 取 `window.data`。
3. 按 `model_input_shape` reshape/permute 成 `(1,15,100)` → 送入 CNN-LSTM 推理。
4. （评估）`GET /labels?machine_id=&t=&t1=0` 取真值，与概率对照。
5. （可选）把预测概率回传前端用于"模型预警"通道。

> 平台侧**不得**对返回值再排序、再归一化、再裁剪列——契约要求逐值使用。

### 8.2 前端展示页

1. `GET /meta` → 取 `features_detail`、`display_subset`、`colors`。
2. `GET /machines` → 渲染机器下拉/列表。
3. 时钟 `t++`：`GET /stream?machine_id=&from_t=&count=60` 拉一批 → 按小多图/状态轨渲染，用 `label`/`warn` 着色，`wrapped_at` 处断线。
4. 播放/暂停/变速/回放均在前端本地控制，服务端无状态。

### 8.3 后续集成到「模拟器调度展示平台」

把「数据适配层（只依赖 `/meta` + `/stream`）」与「图表组件」整体移植；页面其余部分无需感知本服务。详见《数据与前端对接说明》§C.5。

## 9. 变更管理

- 任何 `contract` 字段变更（window_size / 特征顺序 / 归一化 / 形状）必须：升 `contract.version` → 重跑《实施方案》§5.4 契约回归测试 → 更新本文与《数据与前端对接说明》→ 通知两方对接人。
- 新增可选端点（如 SSE、多机批量）走"新增不改动"原则，保持 v1 兼容。
