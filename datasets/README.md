# FJSP/JSP 基准数据集说明

本目录保留了原始扁平基准文件，并生成了当前 DRL-MOFJSP 代码能够直接读取的 `raw/` 和 `add/` 数据。

## 1. 与原数据目录的区别

| 目录 | 文件与组织方式 | 是否包含多目标附加信息 | 当前代码能否直接读取 |
| --- | --- | --- | --- |
| `data_dev` | 400 个扁平 `.fjs` 文件，覆盖 1005、1510、2005、2010 四种规模 | 否，只有原始调度数据 | 否，缺少同名 `add` 文件 |
| `data_test` | 730 个扁平 `.fjs` 文件，包含多种规模及 `Public` 基准子集 | 否，只有原始调度数据 | 否，缺少同名 `add` 文件 |
| `data_dev1` | 200 个文件，即 100 组 `raw/*.fjs` 与 `add/*.fjs` | 是，当前自定义多目标格式 | 是，默认验证数据路径 |
| `data_test1` | 200 个文件，即 100 组 `raw/*.fjs` 与 `add/*.fjs` | 是，当前自定义多目标格式 | 是，默认测试数据路径 |
| `datasets` 原始部分 | 555 个扁平 `.txt` 基准实例 | 否，只有标准 JSP/FJSP 加工数据 | 否，机器编号和目录结构不兼容 |
| `datasets/raw` 与 `add` | 本次生成的 550 组同名配对文件 | 是，附加工序能耗、工件特征和运输矩阵 | 是 |

各数据目录的用途：

- `data_dev`、`data_test` 是早期版本数据，适合存放原始调度实例或与旧版只读取加工数据的代码配合。
- `data_dev1`、`data_test1` 是当前 15 个作业、8 台机器实验使用的完整多目标数据。
- `datasets` 是标准基准集合，覆盖面远大于旧目录，原始部分包含 242 个 JSP 和 313 个 FJSP 实例，共 39 种作业数/机器数组合，范围从 6x6 到 100x20。

## 2. 已完成的数据转换

原始文件没有被删除或覆盖。`prepare_dataset.py` 对所有 `datasets/*.txt` 做了以下转换：

1. 保持作业行中的工序结构和加工时间。
2. 将机器编号从 `0..m-1` 转换为现有代码要求的 `1..m`。
3. 排除 5 个含 0 加工时间的 ORB07 源文件。当前加载器使用 0 表示“该机器不可加工”，因此这些实例不生成对应的 `raw`/`add` 文件。
4. 按原多目标数据格式生成每个工序-机器组合的加工能耗。
5. 生成每个作业的权重、就绪时间、交期、提前惩罚和延期惩罚。
6. 生成对称的机器间运输时间矩阵和运输能耗矩阵。
7. 将每个文件写成 `raw/<实例名>.fjs` 和 `add/<实例名>.fjs`。

附加信息的生成范围沿用项目现有的数据生成逻辑：

| 字段 | 生成范围或规则 |
| --- | --- |
| 加工能耗 | 每个可加工选项随机取 `4-15` |
| 作业权重 | `1-5` |
| 就绪时间 | `0-20` |
| 提前惩罚、延期惩罚 | 各取 `1-10` |
| 交期 | `ready_time + int(1.5 * 各工序平均加工时间之和)` |
| 非对角线运输时间 | `1-3`，矩阵对称 |
| 非对角线运输能耗 | `1-4`，矩阵对称 |

随机值由文件名 SHA-256 派生种子生成，因此重复运行脚本会得到相同结果。生成规则、源文件哈希、转换后文件哈希、实例规模、工序数和可加工选项数都记录在 `manifest.json`。被排除的源文件及原因记录在 `excluded_sources` 中。

## 3. 使用转换后的数据测试

`test.py` 现在支持通过 `test_paras.data_root` 指定数据集根目录，也可以通过 `test_paras.test_files` 只测试指定文件。

要测试全部 550 个已转换实例，将 `config.json` 中的 `test_paras` 调整为：

```json
{
  "num_ins": 550,
  "rules": ["DRL"],
  "sample": true,
  "num_sample": 10,
  "num_average": 10,
  "public_ins": true,
  "data_root": "./datasets",
  "data_path": ""
}
```

只测试一个当前权重匹配的 15x8 实例时，使用：

```json
{
  "num_ins": 1,
  "rules": ["DRL"],
  "sample": true,
  "num_sample": 10,
  "num_average": 10,
  "public_ins": true,
  "data_root": "./datasets",
  "data_path": "",
  "test_files": ["fjsp.brandimarte.Mk03.m8j15c5"]
}
```

测试文件扩展名可省略，`test.py` 会自动补成 `.fjs`。每次请求仍会使用 `num_sample` 个 DRL-S 采样轨迹。

如果只需快速检查文件读取和调度可行性，可以在 `config.json` 中临时把 `num_sample` 调小，例如设为 `2`。大实例（50 到 100 个作业）会显著增加图的邻接矩阵大小和运行时间，建议逐步增加测试规模。

## 4. 重新生成

原始基准文件修改后，可以重新生成配对数据：

```bash
cd /Users/weiwei/Documents/lpw/code/DRL_MOFJSP
python3 datasets/prepare_dataset.py
```

脚本会覆盖 `datasets/raw/`、`datasets/add/` 和 `datasets/manifest.json` 中的派生文件，不会修改原始 `.txt` 文件。

## 5. 数据使用注意事项

- `raw` 和 `add` 必须使用同名文件成对读取。
- 当前权重主要面向 15 个作业、8 台机器的数据训练，其他规模可以完成推理，但结果不应当直接视为同等强度的性能验证。
- 原始 JSP/FJSP 文件通常不包含能耗、交期和运输数据，因此 `add` 中的这些值是为当前多目标模型生成的补充数据，并不是基准原始标注。
- 5 个含 0 加工时间的 ORB07 实例未生成 `.fjs`，原因和完整文件名记录在 `manifest.json` 的 `excluded_sources` 中。原始 `.txt` 基准文件仍保留。
- `manifest.json` 的 `shape_counts` 可用于选择某类规模；测试时通过 `test_files` 精确指定，比直接依赖文件排序更可靠。
