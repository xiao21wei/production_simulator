# 异常发生条件与处置机制

本文描述当前模拟器中订单异常、物料异常和设备异常的实际发生条件、事件流程、处置动作以及状态变化。

当前异常处置遵循统一的事件驱动模式：

```text
异常条件满足
  → 创建异常事件
  → 执行处置
  → 更新生产状态
  → 调整或重新生成生产计划
  → 继续推进事件队列
```

## 1. 订单异常

### 1.1 新增订单

#### 发生条件

当前支持三种新增订单入口：

1. Web 页面点击“手动插单”。
2. 开启“自动插单”开关后，由模拟器自动触发。
3. 直接向模拟器提交 `OrderInsertEvent`。

Web 手动插单或自动插单要求：

- 模拟器已经初始化。
- 当前状态为 `running`。
- 插单期间状态临时切换为 `reoptimizing`，完成后恢复为 `running`。

自动插单的触发条件为：

```text
自动插单已开启
剩余未完成且未取消的 Job 数 <= max(1, initial_job_count // 3)
```

每当仿真事件处理完成后，系统都会检查一次自动插单条件。

每次新增的 Job 数量为：

```text
max(3, initial_job_count // 2)
```

例如初始 Job 数为 15 时，一次自动或手动插单会新增 7 个 Job。

#### 处置方式

新增订单创建 `OrderInsertEvent`，之后执行：

1. 根据当前时间、随机种子和模板 Job 生成完整四工艺 Job。
2. 为整批 Job 创建订单批次，订单号使用提交时刻，例如 `T+9`。
3. 新 Job 加入 `job_queue` 和 `processing_queue`。
4. 当前正在加工的工序保留在原机器上继续加工。
5. 所有未完成工序重新计算机器分配和机器待加工队列。
6. 重新计算运输段、运输时间、运输能耗和计划开始/结束时间。
7. 增加 `plan_revision`，发布新的生产计划。
8. 新 Job 不包含在预先生成的初始物料预算中，因此会消耗现有机器库存，并可能触发物料异常。

主要事件：

```text
OrderInsertEvent
```

### 1.2 取消订单或 Job

#### 发生条件

满足以下条件时可以取消：

- 模拟器正在运行。
- Job ID 存在且合法。
- 批量取消时不能包含重复 Job ID。
- 订单批次 ID 必须存在。

已经取消的 Job 再次取消会按幂等请求返回，不会重复清理。

#### 处置方式

取消单个 Job 或批量取消时创建 `OrderCancelEvent`，之后执行：

1. Job 标记为取消，记录 `canceled_at`。
2. 尚未开始的后续工序标记为 `canceled`。
3. 从所有机器待加工队列和当前计划中移除这些工序。
4. 移除对应开工、完工、补料和物料恢复事件。
5. 正在加工的工序不会被强制终止，允许正常完成当前加工。
6. 已经开始且尚未结束的运输事件可以保留，避免运输状态悬空。
7. 已消耗的物料不会退回。
8. 批量取消时，在全部 Job 预校验通过后统一执行，并更新一次生产计划。
9. 对整个订单批次取消时，仅当批次内所有 Job 都已取消，订单批次才标记为取消。
10. 取消完成后重新整理机器队列、计划状态和生产目标。

主要事件：

```text
OrderCancelEvent
```

## 2. 物料异常

### 2.1 发生条件

四个工艺的每道工序在执行 `OperationStartEvent` 时都会进行物料校验。

校验发生在此前条件均满足之后：

- 机器未处于 `failed` 或 `repairing`。
- 当前工序位于机器队首。
- 前序工序已经完成。
- 运输已经完成。
- 工序尚未开始、完成或取消。
- 当前工序尚未提交过物料消耗。

物料需求来源：

- 冲压：首个领料工序使用 Job 级物料需求。
- 焊装、涂装、总装：使用当前 Task 的物料需求。

异常条件为：

```text
机器当前物料可用量 < 当前工序需求
```

只要任意一种所需物料不足，即触发物料异常。

### 2.2 补料阈值

当前不是只补充缺口，而是把当前工序涉及的全部物料统一补到：

```text
补料阈值 = 当前工序对该物料的需求量 × 3.0
```

补料量为：

```text
max(0, 补料阈值 - 机器当前可用量)
```

如果某道工序因一种物料不足触发补料，则其他低于阈值的工序物料也会一起补足。

默认配置：

```json
{
  "material_replenishment_lead_time": 5.0,
  "material_replenishment_target_factor": 3.0
}
```

### 2.3 处置方式

物料不足时，当前工序不会启动，并保持为机器队首工序。

处置流程：

1. 创建 `MaterialReplenishmentEvent`。
2. 事件记录缺口物料、补料阈值、待补数量和机器当前库存。
3. 补料事件只登记在途数量，不立即增加机器库存。
4. 经过 `5.0` 个仿真时间单位后，创建并执行 `MaterialRecoveryEvent`。
5. 恢复事件将待补物料实际写入机器库存。
6. 再次校验当前工序需求。
7. 库存满足后重新创建 `OperationStartEvent`。
8. 工序真正开始时，按实际需求量扣减物料并设置 `material_consumption_committed=true`。
9. 补料后通常保留约两份当前工序用量，用于后续加工。

恢复前还会检查：

- Job 是否已取消。
- 工序是否已完成或开始加工。
- 工序是否已经移动到其他机器。
- 其他工序是否已经消费了相关物料。

如果工序已经换机，原机器上的在途补料不会入库，新机器会重新执行物料校验。

主要事件：

```text
MaterialReplenishmentEvent
MaterialRecoveryEvent
OperationStartEvent
```

## 3. 设备异常

### 3.1 发生条件

设备异常处置默认关闭，必须配置：

```json
{
  "anomaly_handling": {
    "enabled": true
  }
}
```

支持三种触发方式。

#### 预测报警触发

异常预测接口返回 `is_alarm=true` 时，会对预测机器执行异常处置。

触发前检查：

- 仿真状态为 `running`。
- 机器编号在对应工艺范围内。
- 同一 `(process_id, prediction_time)` 不会重复处理。
- 机器当前没有故障、维修或降效状态。

预测接口当前只使用机器号和报警标志。具体异常类型由模拟器根据种子、预测时刻和机器号确定性选择。

#### 自动设备异常

开启“自动插入异常”后，系统大约每隔 `40` 个仿真时间单位：

1. 从当前无异常机器中随机选择一台。
2. 随机选择一种设备异常。
3. 在允许范围内随机生成持续时间。

#### 手动设备异常

Web 页面可以手动选择：

- 全局机器
- 异常类型
- 持续时间

### 3.2 异常类型与处置方式

| 异常类型 | 持续时间范围 | 默认时长 | 当前处置 |
| --- | --- | ---: | --- |
| `short_failure` 短故障 | 1–5 | 3 | 中断当前加工；等待原机器恢复后重新加工 |
| `medium_failure` 中等故障 | 5–15 | 10 | 中断当前加工；选择加工时间最短的其他兼容机器；创建运输段；等待原机器恢复时点后重新加工 |
| `long_failure` 长故障 | 15–45 | 30 | 中断当前加工；机器标记为故障；对当前工艺执行 DRL 重排并排除故障机器；恢复后再次执行 DRL |
| `degraded` 降效 | 10–20 | 15 | 不中断加工；加工时间放大为原来的 1.5 倍；到期后恢复性能 |

### 3.3 短故障处置

1. 中断当前正在加工的工序。
2. 删除该机器尚未执行的开工事件。
3. 将中断工序重新放入原机器队首。
4. 工序等待原机器恢复。
5. 恢复后重新校验前序、运输、物料和机器状态。
6. 校验通过后重新开工。

### 3.4 中等故障处置

1. 中断当前正在加工的工序。
2. 从该工序的其他兼容机器中筛选非故障、非维修机器。
3. 选择加工时间最短的候选机器。
4. 如果没有其他可用机器，则继续使用原机器。
5. 为换机创建运输时间和运输能耗。
6. 当前实现会等待原机器恢复到 `recovery_time` 后，才允许任务在替代机器重新开始。

### 3.5 长故障处置

1. 中断当前正在加工的工序。
2. 机器状态设为 `failed`。
3. 对只能使用故障机器的未完成工序进行延期。
4. 暂停模拟器并调用 DRL。
5. 以故障机器所属工艺为范围重新分配未完成工序。
6. 重排时排除故障机器。
7. 更新机器队列、运输段和生产计划。
8. 机器恢复后再次执行 DRL，重新利用恢复机器的产能。

### 3.6 降效处置

1. 不中断当前加工。
2. 机器状态设为 `degraded`。
3. 性能系数设为 `1.5`。
4. 当前及降效期间开始的工序，加工时间按 1.5 倍计算。
5. 调整已有工序的完成时间和完成事件。
6. 到期后恢复性能系数 `1.0`。

### 3.7 设备恢复

所有设备异常都会创建 `MachineRecoveryEvent`。恢复时：

1. 清除机器异常类型和恢复时间。
2. 恢复机器性能系数。
3. 将等待该机器恢复的延期工序重新加入队列。
4. 释放满足等待时间的工序。
5. 尝试启动机器队首工序。
6. 长故障机器恢复后再次调用 DRL 重排当前工艺。

恢复后的工序不会绕过正常开工校验。如果物料仍然不足，会继续触发物料补料和恢复流程。

主要事件：

```text
MachineAnomalyEvent
MachineRecoveryEvent
```

## 4. 异常对生产状态和计划的影响

所有异常处置最终都会作用于以下生产状态：

| 状态 | 更新内容 |
| --- | --- |
| 事件队列 | 新增、删除或重排异常、运输、开工和恢复事件 |
| 机器状态 | `idle`、`busy`、`scheduled`、`failed`、`repairing`、`degraded` |
| 机器待加工队列 | 插入、删除、转移或重新排序工序 |
| 物料状态 | 当前可用量、在途量、补料阈值和消耗状态 |
| Job 状态 | 加工中、完成、取消或等待异常恢复 |
| 生产计划 | 重新计算机器分配、开始时间、结束时间和运输段 |
| 目标值 | 重新计算 makespan、energy 和 penalty |

## 5. 当前实现限制

1. 预测结果中的具体异常类型和严重程度尚未使用，异常类型由模拟器按固定种子选择。
2. 物料异常处置目前不考虑订单优先级，只按机器队首和执行顺序处理。
3. 中等故障虽然会选择替代机器，但会等待原机器恢复时间点后才开始加工。
4. 长故障只对故障机器所属工艺执行 DRL 重排，其他工艺随前序完工时间变化自然调整。
5. 取消 Job 不会退回已消耗物料。
6. 初始物料只覆盖数据集内已有 Job，动态插单未纳入初始物料预算。
